# 视析 · 视频智能分析 2.0

上传本机视频，在浏览器内检测人员与车辆。提供分析画面、当前分析帧计数、目标档案、截图核对、可选视觉模型精细识别及 Excel 导出。

## 2.0 修复：航拍视频零检测

使用用户提供的 `245030.mov` 复现了旧版的问题：H.264，3840×2160，25 fps，22.08 秒。旧版 COCO-SSD 轻量模型以整图方式检测，3 秒帧在默认 0.55 阈值下没有目标。降低阈值或保留原来的整图处理不能可靠解决小目标问题。

修复内容：

- 检测引擎替换为官方 YOLOX-Tiny 0.1.1rc0，使用 ONNX Runtime Web 1.20.1 单线程 WASM。
- 使用独立 Worker 保持页面响应；不支持 Worker 时可切换主线程兼容模式。
- 保留最长边 3840 像素的图像；4K 横屏通过整图加 15 个重叠分块推理，原始坐标统一后去重，并剔除分块边界的重复碎框。
- 默认完整抽帧、每秒 1 帧、检测置信度 40%；近景可以选择快速整图检测。航拍分块时人员门槛至少 60%，降低本段视频中路牌和路灯误判为人员的问题。
- 播放画面改为展示最近完成分析的原始帧；数量、目标框与该帧对应。后台准备下一帧期间保留已完成的画面。
- 增加模型下载百分比和每帧分块进度，明确区分尚未处理、处理完成且零目标、加载失败。
- 处理播放结束时仍在进行的推理，修复检测框随旧帧超时消失的问题。
- 轨迹编号与当前数量分开。当前使用短时位置关联，不能将累计轨迹数解释为去重车辆数。

## 功能与使用

1. 上传可由浏览器解码的视频，优先 H.264 MP4 / MOV。
2. 保持默认设置，或选择航拍 / 远景增强。点击开始分析，等待首帧分块进度完成。
3. 点击目标档案核对截图、视频时间与模型输出。
4. 需要外观细节、品牌型号及车牌时，配置兼容 Chat Completions 图片消息的视觉模型接口、模型名与 API Key，并启用。
5. 导出 Excel。包含分析概要、目标档案、逐帧统计、逐帧检测、精细识别 5 张表。

基础检测在本机浏览器中执行。仅主动启用精细识别后，目标截图才会被发送到用户配置的服务商。密钥与记录只保存在当前页面内存；刷新或关闭前请导出。

## 能力边界

- 航拍增强每帧包含多次推理，处理速度取决于设备性能，不能承诺按原视频帧率实时运行。
- 本段视频车辆较小、视角倾斜，存在漏检与类别混淆。模型计数是检测输出，不是人工标注的真实总量。
- 地面标志、路灯和其他外形相近物体会造成误检；人员的更高门槛也会降低模糊人员的召回率。
- 航拍摄像机移动较快，低采样率下轨迹会断裂并产生新编号。累计轨迹数不是唯一车辆或人员数。
- 像素颜色为候选。精确车型与车牌需清晰证据及用户接入的模型；不将未知细节补为确定结果。
- 每帧最多 250 个合并目标；单次会话最多约 1,000 条轨迹、100,000 条逐帧目标记录或 100,000 个分析帧，到达上限自动暂停。
- Excel 不嵌入截图；截图在页面内查看。

## 验证（2026-10-04）

- 对附件原视频解码帧执行生产版预处理、真实 ONNX 权重推理、分块合并、页面记录与 Excel 写入回读。测试不将模拟框作为模型结果。
- DOM 环境模拟视频事件；模型、原始图像、Canvas 和 Excel 数据真实。此执行环境不提供受支持的真实浏览器预览通道，浏览器原生解码及 Worker UI 流程未作为本次完整端到端验证结论。
- 核心回归：`node tests/core.test.cjs` 与 `node tests/detector.test.cjs`。
- 完整逐秒验证覆盖 0–22 秒的 23 个抽样帧：每帧有 3–19 个车辆检测输出，人员过滤后为 0；导出 197 条逐帧目标记录。该数字是模型输出，不是人工标注准确率；累计 169 条轨迹包含快速移动航拍导致的断裂与重复编号。
- 在本次 CPU/WASM 测试环境，23 帧处理耗时约 114 秒。用户设备速度会不同。
- 原视频及用户数据未提交到站点代码或发布资产中。
