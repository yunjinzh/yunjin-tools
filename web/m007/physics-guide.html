2. 状态机：状态、守卫、失败出口

公共执行周期为 120 Hz。每次转换写入事件。任意非终态出现硬失败都进入 FAILED，停止后续机器人运动命令并保留证据；已建立的抓取约束在普通规划故障中保持，接触丢失或受力不足时拆除。E_STOP 停止运动命令，仿真物理仍可推进；恢复采用重置重跑。

场景与碰撞台面、地面、主障碍使用固定刚体；Rapier broad phase + narrow phase；物体穿透通过接触流形和独立 shape-distance 双检。手臂是简化代理，非全部 CAD 三角面碰撞；桌脚仅视觉结构，原平台全部 SimReady 资产尚未逐项配齐碰撞参数。
自身碰撞右前臂胶囊与躯干盒检测；肩部相邻关节接触排除。尚未建立全身 Allowed Collision Matrix。正式接入应覆盖非相邻双臂、腿、躯干、末端、负载所有组合。

接触矩阵与扫掠体

夹指—目标物接触只在 CLOSE 至 RETREAT 等操作阶段许可；物体—源台面只在取物阶段许可；物体—目标台面只在 LOWER、RELEASE、RETREAT、SETTLE、SUCCESS 许可；物体—普通障碍接触一律记为错误。把允许的接触对写成对称关系，不能通过关闭全部碰撞来“解决”误报。

运动学刚体不会自动被接触力挡住，因此每次提交 setNextKinematicTranslation 之前做 shape cast。负载有独立扫掠体；不能只检查机器人基座。旋转运动按半径×转角细分，使每段估计表面运动不超过 3 mm。运行中遇到新障碍直接停止；LOWER 仅为目标台面接触开放白名单，其余碰撞继续检查。

抓取判定

接触条件：左右指均有真实流形接触，接触距离 < 1 mm；
法向条件：n_left.x × n_right.x < -0.65（当前夹持轴为世界 X）；
承载条件：F_available = 2 μ min(N_left, N_right)
          F_required = 1.5 × m × (g + |a_filtered|)
          F_available ≥ F_required，且每指实测力 ≤ 80 N；
持续条件：上述条件连续满足至少 0.18 s。
N = 法向接触冲量之和 / 固定物理步长。
a_filtered 用最长 0.10 s 速度窗口计算，避免把高频接触解算噪声误判为持续加速度。

上述预算只近似评估夹持轴外的载荷保持能力，不能替代完整的六维抓取扳手分析。闭合期不满足力预算则拒绝建约束；搬运中双侧接触丢失超过 0.10 s，或力预算不足持续超过 0.18 s，拆除抓取约束并记录失败。

import { PhysicsTrial, initPhysics } from './physics/core.js';
import { FixedClock } from './physics/clock.js';

await initPhysics();
// rig 是原项目 RobotRig，已 build/load，且 root.parent 是机器人容器。
const trial = new PhysicsTrial({ rig, kind: 'cup', seed: 1 });
const clock = new FixedClock(() => trial.step());
trial.start();

function frame(renderDeltaSeconds) {
  clock.advance(renderDeltaSeconds); // 每次求解始终是 1/120 s
  const body = trial.payload.body;
  mesh.position.copy(body.translation());
  mesh.quaternion.copy(body.rotation());
  renderer.render(scene, camera);
}
// 证据导出
const evidence = trial.report();
// 场景销毁，释放 WASM 物理资源
trial.dispose();

// 代码节选。只有 gripAttach() 的完整守卫通过后才执行。
const before = payload.body.translation();
const offset = subtract(before, palm.body.translation());
const orientation = payload.body.rotation();
const joint = world.createImpulseJoint(
  RAPIER.JointData.fixed(offset, orientation,

7. 在现有训练场中逐步接入

  1. 当前已完成：原项目增加独立 route physics.html 与导航入口；共用现有 G1 资源、RobotRig 和 planner.js；保留原训练平台。
  2. 下一步迁移旧取放：在现有 Simulator 增加 PhysicsAdapter，将 pick/place/move 映射到本状态机。物体的 position/quaternion 改为只读物理同步；把 attach、lerpVectors 物体动画限定于历史回放层。迁移后替换旧的“父子关系必须绑定”测试为物理验收测试。
  3. 模型资产标定：每件杯/箱保存 visual、collision、mass、inertia、COM、friction、restitution、grasp frames、support surfaces、来源与标定区间。动态凹形用凸分解或多凸体，静态复杂环境使用简化碰撞体；对杯柄、柜格等任务关键接触区单独验证。
  4. 物流扩展：先完成轻量单夹爪箱体，再实现双臂接触、闭链约束、左右载荷分担、力矩/重心约束和柜格开口检测。箱体尺寸变化后要重新计算夹爪跨度、抓取点与整个负载包络，不仅调整显示网格。
  5. 咖啡扩展：先完成空杯/加盖常温容器取送；再增加咖啡机按钮受控接触、设备反馈和出液状态。倾倒需独立的液体/容器模型及液面晃动指标，不应仅用杯体保持竖直来宣称不会洒出。
  6. Real2Sim2Real：采集实物尺寸/质量与接触实验 → 标定资产区间 → 在冻结场景生成并筛选轨迹 → 真机按同一任务配置受控执行 → 对齐关节、末端与接触时序 → 受控干预区分根因 → 更新参数并重复仿真与真机对照。

后续真机运动规划可接入 MoveIt PlanningScene 的自碰撞和环境碰撞检查，将已抓取物体作为 attached collision object 纳入路径规划，并只对白名单接触开放碰撞。规划层的“attached object”是碰撞计算关系，不能直接替代真实夹持力反馈。

移交接口原则：渲染只读状态；物理内核拥有动态物体位姿；控制器只提交机器人/夹爪命令；感知产生带时戳与坐标系的观测；评测器独立计算成功。训练结果和回放文件与执行现场分离，重置时重建世界并使旧约束失效。
